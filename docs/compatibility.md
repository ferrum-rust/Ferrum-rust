# Minecraft 1.8.9 호환 현황 — Ferrum v0.4

전체 Rust / Vulkan 구현을 유지한다. Java는 로컬 원본 결과를 얻는 검증 도구로만 실행한다. 전체 바닐라 복제, 100배 성능, 공개 서버 안티치트 통과는 아직 달성/검증하지 않았다.

## v0.4 이후 작업 중인 네이티브 월드 엔진

DEFAULT 일반 플레이는 generator 4의 원본 population을 사용한다. 생성 작업 스레드를 유지하며 스트리밍하고, 생성된 개체·상자와 기존 블록 변경을 플레이 경로에 연결했다. 게임 틱은 기존 Simulation 한 곳에서 진행하며 생성 호스트에서 중복 실행하지 않는다. 전체 호환 완료 판정은 하지 않았다.

- 원본 `WorldServer`와 전체 오버월드 생성 순서를 비교한 24개 구조물 중심 영역/384개 청크에서 전체 블록·조명 배열과 요청별 두 난수 상태가 일치했다. 주민 직업 42개, 상자/디스펜서 인벤토리 33개, 스포너 9개도 비교했다. 24개 영역 모두 요청마다 JSON 저장/복원을 끼운 검사도 통과했다. 이 과정에서 레일·횃불·가구 방향·주민 초기화·잎 덮개 콜백의 차이를 수정했다.
- 광원 엔진은 8개 실제 월드의 128개 체크포인트에서 햇빛/블록 빛, 높이표, 청크 섹션, 반블록 조회, 초기 조명 처리, 분할 재검사를 비교했다. 식생 이웃 조건·쓰기 순서·드롭 난수는 50,244개 원본 콜백 사례를 통과했다.
- 실제 월드의 샘물·용암·즉시 낙하·식생 파괴 조합 504개에서 최종 블록, 아이템 종류/수/좌표 비트, 두 난수 상태를 비교했다. 이 중 168개는 주변 9개 청크의 전체 조명 해시도 일치했다. 예약 큐를 공유하는 중첩 콜백과 기존 저장 형식 복원도 검증했다.
- 61개 바이옴 장식 단계, 사원/마녀 오두막/요새/해저 유적/네더 요새를 독립 원본 실행으로 검증했다. 동물 배치 5,124개 사례, 동물 초기화 3,072회, 블록 드롭 49,299개 사례도 통과했다. 이러한 개별 검증이 모든 개체 AI·도구 수확·전체 월드 통합의 완료를 뜻하지는 않는다.
- 네더/엔드 밀도·표면·동굴·블록과 생성 난수, 각 차원 장식 순서의 원본 자료를 추가했다. Java 8u202/8u501과 Java 25를 교차 비교해 네더 밀도 일부의 1 ULP 차이를 확인했고, 원본 1.8.9 기준은 Java 8로 고정한다. 검증된 252개 청크의 최종 블록은 세 JVM에서 같았다. 상세 범위는 `reports/dimension-java-version-comparison.json`에 남겼다.
- 월드 스폰 선택은 실제 `WorldServer`의 8개 시드와 1,000회 탐색 제한 사례를 비교했다. 시드 189는 `(-116, 64, 311)`이다. 원본 서버와 같은 순서로 시작 영역의 625개 청크를 전부 생성하여 각 청크의 블록·조명, 생성 플래그, 제공자와 월드 난수를 비교했다. `start.bat --fresh --seed 189 --render-distance 4 --screen native-spawn --screenshot reports/native-spawn.png`으로 이 영역을 Vulkan에서 확인할 수 있다. 이 생성 단계를 DEFAULT 일반 새 게임에도 사용한다.
- 플레이어 좌표·속도·충돌 상자를 f64로 유지한다. 원본 `EntityPlayerSP` 9,240틱에서 걷기/달리기/점프/수영/사다리/비행, 더블탭, 착지 해제, 속도·감속·점프·실명·물갈퀴 조합을 비교했다. 원격 보정과 이동 패킷도 이 상태를 사용한다. S20 속성 스냅샷 197개, 효과 추가/제거 패킷 360쌍과 효과 수명 120단계를 대조했다. 블록 충돌은 1,394개 상태, 이웃 조합, 이동 중인 피스톤을 비교했다. 개체 간 밀기·전체 속성·공개 서버 검증은 남아 있다.
- 원본 라이트맵 색 921,600개, 태양 계산 756개, AO 36,288개 사례, 횃불 밝기 변화 6,000틱이 일치했다. Anvil/원격 청크의 광원 배열을 보존하고 카메라가 움직일 때 고정된 라이트맵을 다시 보내지 않는다. 실제 Vulkan 화면에서 AO, 야간 투시, 흡수 체력을 확인했다. 날씨·보스 효과와 특수 모델에는 차이가 있다.
- 일반 횃불과 켜진/꺼진 레드스톤 횃불은 로컬 JAR의 바닥·벽 모델을 읽는다. 15개 상태의 면 90개에서 정점 360개의 위치·UV 비트를 원본 FaceBakery와 대조했다. `--render-distance 8`처럼 값을 명시하면 저장된 그래픽 설정보다 명령행 값이 우선한다.
- 일반 싱글플레이도 새 낙하 엔진을 사용한다. 원본 모래·자갈·모루 개체 52,353틱, 낙하 시작 1,008개 사례, 착지 대상 1,394종, 실제 WorldServer의 통합 1,285틱을 비교했다. 기존 f32 낙하 개체 저장을 읽어 이어가고, 신규 저장은 충돌 상자와 난수 상태까지 보존한다. 전역 아이템 개체 순서, 포털·회로 접촉, 모든 피해 콜백 순서는 별도다.
- 아이템 스택은 타입별 NBT와 인챈트를 보존하며 수정 시 복사한다. 스택 참조 유지와 새 스택 생성도 구분한다. 실제 피해 경로에 방어구·보호·저항·흡수·모루 피해를 연결했고, 방어구 5,552개, 복합 방어 2,560개, 낙하 물체 피격 960개 사례를 비교했다. 우클릭한 틱부터 아이템 사용을 진행하며, 원본 24×48틱과 채굴·획득·설치·섭식·사망·저장 통합 검사를 통과했다.
- generator 4용 단일 작업 스레드 호스트의 명령 순서, 오래된 블록 수정 거절, 월드 잠금, 원자적 저장/복원, 인챈트 전리품 변환을 검사했다. DEFAULT 일반 플레이는 생성 상태와 Simulation 저장을 `saves/native-v4/<저장 ID>/world.json.gz`에 함께 기록한다. 이전 generator 3 저장은 별도 v4 체크포인트로 옮기며 원래 파일을 보존한다. 생성 호스트와 기존 게임 틱 사이의 모든 전역 난수/콜백 순서까지 통합한 것은 아니다.

원본 Java 실행은 검증 스크립트에서만 한다. `scripts/vanilla_world.py`의 `java_executable()`은 설치된 Java 8u501을 우선하고 `MC189_JAVA`로 비교 대상 JVM을 지정할 수 있다. 이전 스크립트 중 아직 PATH의 Java를 사용하는 것은 개별 확인이 필요하다. Rust 런타임에는 Java 호출이 없다. JSON에는 `float_roundtrip`을 사용해 f64 좌표의 저장/복원 손실을 방지한다.

### 싱글플레이에서 추가로 비교한 동작

- 오버월드 안개·하늘색·수중 시야와 포션 효과의 수식은 로컬 JAR의 실제 렌더러 1,536개 조합으로 대조했다. 밝기 보간 256틱과 화려한 나뭇잎 내부 면을 확인했다. Vulkan 렌더러는 원본의 시야 거리별 안개 구간, 바이옴 온도, 플레이어 눈높이를 적용한다. 태양·달 텍스처는 로컬 자원에서 읽는다.
- 태양·달·노을 모델 168개 장면과 별 정점 3,120개를 대조했다. 달의 여덟 위상, 비와 노을을 포함한 원본 OpenGL과 Vulkan의 표본 픽셀 1,430개에서 채널별 차이는 255단계 중 최대 2였다. 눈 덮인 잔디와 대체 블록 옵션을 포함한 잔디 모델은 원본의 면 46개와 좌표 80곳에서 UV 및 위치별 모델 선택을 비교했다.
- 비·천둥 전환에 쓰이는 타이머, 월드 난수, 강도 보간은 실제 `World.updateWeather` 64개 시나리오의 초기 상태 및 16,384틱과 대조한다. 기존 Anvil의 날씨를 읽고 프로젝트 저장으로 이어가며 잠든 뒤에는 원본 순서대로 비와 천둥을 해제한다. 원본 rain/snow 텍스처로 강수를 그리며 바이옴·고도·지붕을 판정한다. 추운 지역의 결빙·적설과 블록 빛에 의한 눈/얼음 융해도 게임 틱에서 처리한다. 번개 피해는 별도다.
- 지형을 세로 16칸 단위로 나눈 뒤, 가려진 구역은 원본의 여섯 방향 연결 판정으로 그리기 대상에서 제외한다. 원본 `VisGraph` 136개 사례가 비교 대상이다. 로드되지 않은 영역 너머와 시점이 고체 내부에 있는 경우에는 과도한 컬링을 피한다. 움직이지 않는 시점의 그리기 명령과 변하지 않은 광원·GUI 버퍼도 재사용한다.

- 저장된 오버월드 플레이어의 좌표·속도·시선·비행 상태와 침대 스폰을 실제 `EntityPlayerMP.readFromNBT` 64개 사례와 비교했다. 일반 사망 화면에서 부활할 때 침대의 네 방향, 막힌 출구, 침대가 사라진 경우, 강제 스폰을 구분한다. 블록 상태 1,394개와 침대 주변 배치 512개의 출구 순서를 원본과 대조했다. 일반 싱글플레이의 침대 설치 1,728회, 취침·기상 288회, 하루 24,000틱, 실제 WorldServer의 취침·기상 560틱을 비교했다. 사용자는 밤에 자고 떠날 수 있으며 주변 몬스터, 막힌 출구와 개인 스폰을 구분한다. 황천 침대 폭발과 차원 간 부활은 별도다.
- 마우스로 가리킨 개체와 블록 선택은 원본 렌더러 486개 장면에서 비교했다. 벽을 사이에 둔 대상, 탑승 중인 대상, 같은 거리에 놓인 개체를 포함한다. 실제 개체 상호작용 패킷 본문 377개도 비교했다.
- 아이템·경험치 구슬·낙하 블록·플레이어가 섞인 실제 서버 42개 장면의 2,730틱에서 움직임, 획득 순서와 난수 상태를 비교했다. 주민 거래 수량·재입고·거래 경험치와 1,800개 몹 경로를 원본과 대조했다. 일반 플레이의 모든 개체는 아직 이 서버에서 실행되지 않는다.
- 1인칭 빈손 모델의 피부·소매 정점 48개, 원본 ItemRenderer가 만든 모델뷰 행렬 28개, 휘두르기 1,792틱을 대조했다. 침대 머리와 발 모델의 면 60개도 원본 FaceBakery 결과와 비교했다.
- 물·용암·불·포털·프리즈머린·바다 랜턴 등 원본 블록 애니메이션 9종을 20Hz로 진행한다. 원본 GPU 출력 1,630개 시점에서 5개 mip 레벨을 비교했다. 원본 32픽셀 흐름 텍스처는 현재 16픽셀 블록 배열에 맞춰 샘플링한다.
- Vulkan은 원본의 반투명 블록 8종을 불투명한 면 뒤에 그린다. 물·얼음·색유리 등의 면을 카메라에서 먼 순서로 정렬하고 변경된 인덱스를 갱신한다. 유리판의 16색, 일반 유리판, 철창의 연결 방향 288가지에서 원본 모델 면 2,800개의 좌표·UV·텍스처·음영과 면 생략 방향을 비교했다.
- 일반 월드의 프로젝트 저장 형식 2는 블록과 플레이어 상태를 함께 교체한다. 형식 1의 분리된 두 파일에서 읽는 경로, 다음 저장 실패, 부분 임시 파일과 오래된 플레이어 파일이 남은 경우를 검사한다.
- 네이티브 서버의 채굴은 C07 입력 330개 장면의 10,560개 시점, 우클릭은 C08 입력 1,248개 장면을 원본과 대조했다. 불의 설치·포털 생성과 제거 518개 시점, 예약된 불의 갱신 1,640개 시점에서 블록·난수·예약 순서를 확인했다. TNT 점화 요청은 저장되며, TNT 물리와 폭발을 처리할 때까지 그 월드의 진행을 보류한다.
- `native-spawn`과 `native-player-spawn`은 새 네이티브 월드 호스트에 명령을 보내 625개 청크와 처음 접속하는 플레이어를 준비한다. 두 장면과 경험치 구슬 11단계는 RTX 3050 Laptop GPU에서 Vulkan 캡처로 확인했다.

| 영역 | 현재 동작과 증거 | 남은 차이 |

| 난수/노이즈/바이옴 | 원본 JAR의 출력과 비교; 음수 시드/좌표, Java 연산 순서와 GenLayer 그래프 | DEFAULT 외 월드 종류·모드 |

## 검증 실행

```bat
cargo test --locked
python scripts/test_vanilla_inventory.py --fixtures-only
cargo test --locked -- --include-ignored
cargo clippy --all-targets --locked -- -D warnings
python scripts/test_legacy_world.py
```

`tests/fixtures/vanilla189-*.json`에는 원본에서 얻은 숫자·블록 상태·NBT 관측값을 저장한다. 원본 소스/게임 자산은 저장소에 포함하지 않는다. `tools/java/*Oracle.java`는 실제 원본 클래스를 실행하며, `scripts/test_vanilla_*.py`와 관련 `*_fixtures.py`에서 재생성할 수 있다. Java/JDK와 로컬 매핑 JAR은 oracle 재생성에만 필요하다.

기존 v0.4 지형 검사는 population 전 ChunkProviderGenerate 출력이고, 마을·폐광·장식의 개별 부품 검사는 합성 지형에 원본 부품을 실행한 결과다. 이후 추가한 24개 영역 검사는 실제 WorldServer의 생성/로딩/이웃 콜백을 포함한다. 어느 쪽도 모든 시드와 모든 플레이 상황을 포괄했다는 뜻은 아니다. 인벤토리 검사는 원본 ContainerChest의 slotClick을 실행한다.

전체 호환 판정에는 원본의 로딩/틱/입력 순서를 보존한 통합 비교가 추가로 필요하다. 올바른 패킷 ID와 이동 테스트만으로 prediction 안티치트 통과를 보장할 수 없다. 원격 이동의 f64 전환은 완료했지만 전체 충돌 형태와 속성·효과·패킷 의미 검증은 남아 있다.
