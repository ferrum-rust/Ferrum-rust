# Ferrum 1.8.9 — Rust / Vulkan 싱글플레이 클라이언트

`start.bat`을 실행하면 메인 메뉴가 열립니다. 싱글플레이에서 기존 1.8.9 월드를 선택하거나 서바이벌·크리에이티브 월드를 만들 수 있습니다. 새 크리에이티브 월드는 빈 핫바로 시작하며, E를 눌러 원하는 아이템을 꺼낼 수 있습니다.

월드에서 **Esc → LAN 서버 열기**로 들어가 다른 플레이어의 게임 모드와 치트 허용 여부를 선택한 뒤 **LAN 세계 시작**을 누르세요. 같은 네트워크의 멀티플레이 목록에 월드가 표시되고, 호스트의 채팅창에는 접속 포트가 표시됩니다. 월드에서 나가면 공유가 종료됩니다.

이 프로젝트는 원본과 아직 차이가 있는 네이티브 구현입니다. Java 게임을 실행하거나 OpenGL로 우회하지 않습니다. **전체 Minecraft 1.8.9 포팅 완료, 모든 최적화 완료, 100배 FPS 달성을 의미하지 않습니다.**

## 실행

```bat
start.bat
start.bat --play --creative
start.bat --play --generator 2 --village
start.bat --world "%APPDATA%\.minecraft\saves\New World-"
start.bat --list-worlds
```

이미 빌드된 release 실행 파일이 있으면 바로 실행합니다. 소스를 다시 빌드하려면 `set FERRUM_REBUILD=1` 후 `start.bat`을 실행하세요. 첫 리소스 준비에는 Python이 필요합니다. 직접 실행하려면 프로젝트 폴더에서 `target\release\ferrum189.exe`를 실행하세요. Vulkan을 지원하는 GPU 드라이버가 필요합니다.

## 현재 원본 비교 결과

일반 DEFAULT 새 게임은 generator 4를 사용합니다. 원본 순서로 지형·동굴·구조물·광석·나무·풀·꽃·얼음·눈을 생성하고, 같은 생성 상태를 유지하며 주변 청크를 불러옵니다. 아래 명령은 일반 저장 파일을 만들지 않고 시드 189의 스폰 영역을 생성해 Vulkan으로 표시합니다. 첫 번째는 해안 전경, 두 번째는 처음 들어온 플레이어의 시점입니다.

```bat
start.bat --fresh --seed 189 --render-distance 8 --screen native-spawn --screenshot reports\native-spawn-189.png
start.bat --fresh --seed 189 --render-distance 6 --screen native-player-spawn --screenshot reports\native-player-spawn-189.png
```

시드 189의 월드 스폰은 `(-116, 64, 311)`입니다. 원본 서버와 같은 순서로 시작 영역 625개 청크를 요청해 블록·조명과 난수 상태를 비교했습니다. 기존 1.8.9 오버월드를 열 때는 저장된 플레이어 좌표 주변의 청크를 읽습니다. 개인 침대 스폰과 강제 스폰을 복원하며 사망 화면에서 부활할 때 침대 주위의 바닥과 머리 공간을 검사합니다.

일반 싱글플레이의 저장 파일은 프로젝트의 `saves`에 있습니다. DEFAULT의 새 저장은 `saves/native-v4/<저장 ID>/world.json.gz`에 생성 상태와 플레이어·인벤토리·블록 변경·시뮬레이션을 함께 기록합니다. 예전 generator 3 DEFAULT 월드를 열면 기존 변경 내용을 이 새 저장 방식으로 옮기며, 이전 저장 파일은 보존합니다. 저장 도중 중단되면 마지막에 교체를 마친 시점에서 이어집니다. `--fresh`는 임시 월드로 실행하며 저장하지 않습니다.

DEFAULT 월드의 30초 자동 저장은 화면을 멈추지 않고 작업 스레드에 전달합니다. 저장 요청 시점의 블록 변경과 플레이어 상태를 함께 고정하며, 이후 플레이 중 변경은 다음 저장에 반영합니다. 월드를 나갈 때는 마지막 저장 완료를 기다립니다. 새 월드에 들어가면 자동 저장 타이머를 다시 시작합니다. 초기 지형 계산은 병렬로 준비하고, 구조물·식생 배치와 난수 반영 순서는 원본대로 유지합니다. 로딩 화면에는 생성·업로드 진행률이 표시됩니다.

빈 지도는 우클릭하면 탐색 가능한 지도가 되며 지도 데이터는 월드와 함께 저장됩니다. 경험치 병은 우클릭 투척 후 충돌 시 경험치를 생성합니다. 명령 블록은 치트를 허용한 월드의 크리에이티브 모드에서 우클릭해 편집하고, 레드스톤 신호가 켜지면 1틱 뒤 명령을 실행합니다. 인벤토리의 상태 효과는 사용자 요청에 따라 I와 V 이상도 표시합니다. 이 단계 표시는 해당 구간을 생략하는 원본 UI와 의도적으로 다릅니다.

## v0.4에서 시작한 원본 비교와 수정

게임 실행은 **전체 Rust / Vulkan**을 유지합니다. Java는 개발 중 원본 출력 값을 얻는 검증 도구로만 사용하며 `start.bat`이나 게임의 월드 로딩에서 실행하지 않습니다.

- 기본 DEFAULT 새 월드는 `--generator 4`입니다. 실제 플레이에도 원본 population 단계를 연결했습니다. `--generator 3`은 저장 ID 없이 실행하면 지형만 비교하는 경로로 남아 있습니다. 평지·증폭·대형 바이옴·사용자 지정은 기존 생성 경로를 사용하며 DEFAULT와 같은 통합 범위를 의미하지 않습니다.
- 마을·폐광·요새 등 구조물, 광맥·호수·던전·바이옴별 식생과 눈을 원본 콜백 순서로 생성합니다. 원본에서 추출한 청크·조명·난수 상태와 비교하며, 청크 요청 순서와 저장된 생성 상태를 유지합니다. 아래 `--structure-preview`로 마을/폐광을 독립적으로 볼 수도 있습니다.
- 모래/붉은 모래/자갈의 예약 낙하, 물·용암의 예약 흐름, 물의 수원 생성, 용암 혼합, 흐름 높이·물살과 낙하 중 블록 렌더링을 추가했습니다. 물·용암은 손 채굴 대상에서 제외하고 양동이는 수원만 선택합니다. 예약 틱과 낙하 개체는 저장됩니다.
- 크리에이티브 비행을 멈출 때 속도를 0으로 지우던 동작을 고쳤습니다. 수평 관성과 수직 감쇠, 비행 전환과 충돌을 적용합니다. 전체 플레이어 물리가 Java와 비트 단위로 같다는 뜻은 아닙니다.
- 54칸 큰 상자, 막힌 뚜껑, 상자 절반별 저장, 더블 클릭 모으기, 드래그 분배, Shift 이동, 숫자 키 교환, 크리에이티브 복제, 슬롯에서 버리기를 연결했습니다. 창 닫기의 커서/제작 재료 드롭도 수정했습니다.
- 원본 잔디/나뭇잎 색상표, 바이옴·고도·3×3 이웃 색 혼합, 가문비/자작 잎 색, 잔디 측면 덧씌우기와 눈 덮인 잔디를 적용했습니다. 원본 색 15,624개를 대조했습니다.
- Java signed long·UTF-16 문자열 해시로 시드를 해석합니다. `--seed -1`, 최솟값과 문자열 시드를 지원합니다. 메뉴의 빈 시드/숫자 0은 원본처럼 무작위 시드입니다.
- 기존 v1/v2 저장은 생성 방식과 저장 식별자를 유지합니다. v3 DEFAULT 월드의 업그레이드는 별도의 v4 저장으로 진행하며, 기존 파일과 플레이어가 수정한 블록을 보존합니다. 이전 저장에 이미 남은 블록 변경까지 원본의 미수정 지형으로 되돌리지는 않습니다.

전체 구현 범위는 [호환 현황](docs/compatibility.md), 패킷 범위는 [프로토콜 문서](docs/protocol-47.md)에 기록합니다.

```bat
start.bat --play --creative --seed -1
start.bat --structure-preview village --screenshot reports\native-village.png
start.bat --structure-preview mineshaft --screenshot reports\native-mineshaft.png
start.bat --screen terrain --screenshot reports\native-terrain.png --fresh
start.bat --screen fluids --screenshot reports\fluids-v04.png --fresh
start.bat --screen doublechest --screenshot reports\doublechest-v04.png --fresh
```

구조물 미리보기는 원본 후보 청크를 검색하고 고정된 순서로 해당 구조물만 배치하는 별도 검증 장면입니다. 게임 저장에 섞지 않으며 `reports/structure-preview.json`에 부품·주민·상자 광산 수레·스포너 생성 정보를 기록합니다. 광산 수레/스포너 동작 구현을 의미하지 않습니다. 폐광 PNG는 주변 암석을 제거한 검증용 단면 장면입니다. 구형 Ferrum 자체 생성 월드를 보려면 `--generator 2 --village`를 지정합니다.

## 기본 기능

- 원본 파노라마, Minecraft 로고, 버튼, 한글/유니코드 폰트, 언어 선택, 월드 선택·생성, 일시 정지, 사망 화면.
- 소유한 JAR의 리소스·팩 아이콘 3,086개와 공식 asset index의 734개를 `.local/resources`에 가져옵니다. 총 3,820개 파일이며 게임 언어 75개, 별도 Realms 언어 파일, OGG 사운드 578개를 포함합니다. Realms는 실행하지 않습니다.
- 원본 이미지로 표시하는 9칸 핫바, 36칸 소지품, 방어구 4칸, 아이템 이름·개수·도구 내구도, 체력·허기·방어력·공기·경험치 HUD.
- 좌클릭 이동, 우클릭 분할·한 개 놓기, Shift 클릭 이동, 숫자 키 교환, 2×2/3×3 제작, 크리에이티브 아이템 목록. 나무·판자·막대·도구·방어구·작업대·상자·화로·횃불 등 기본 제작법을 지원합니다.
- 채굴 진행도와 균열, 도구/재질에 따른 속도와 드롭 조건, 내구도, 블록 설치 시 수량 차감, 아이템 투하·중력·합치기·줍기·소멸.
- 서바이벌 체력·허기·포만도·음식 섭취·낙하/질식/용암/전투 피해·사망 시 아이템 드롭·리스폰. 수영과 웅크리기 가장자리 방지, 크리에이티브 비행.
- 싱글플레이에서 1.8.9의 몹 32종을 불러오고 저장하며 Vulkan으로 그립니다. 원본에 소환 알이 있는 27종은 크리에이티브 인벤토리에서, 전체 32종은 치트를 켠 월드에서 `/summon`으로 소환할 수 있습니다. 예를 들어 `/summon Guardian ~ ~ ~ {Elder:1b}`는 엘더 가디언을 소환합니다. 눈 골렘·철 골렘·위더는 원본 블록 조합으로도 만들 수 있습니다.
- 원본 상자/화로 GUI, 상자 보관, 연료 소비와 제련. 인벤토리·제작대·상자·화로를 열어도 시뮬레이션이 진행됩니다. Esc 일시 정지와 설정에서는 멈춥니다.
- 원본 메뉴/게임 음악, 버튼·채굴·설치·줍기·먹기·피해·발소리와 기본 몹 소리. 볼륨 조절.
- 기존 legacy Anvil/NBT 청크와 플레이어 소지품·방어구·체력·허기·경험치·시각, 상자·화로 내용을 읽습니다. 오버월드에 저장된 플레이어의 좌표·속도·시선과 비행 상태를 복원하며 이후 변경 사항은 프로젝트의 저장 폴더에 기록합니다.

## 그래픽 설정과 최적화

2026-11-08 시각·청크 로딩 수정: 하늘 배경이 깊이 버퍼를 덮어 해·달을 줄무늬로 가리던 경로를 수정했습니다. 실제 Vulkan에서 1920×1080 등 15개 장면을 비교하고, 지형 뒤의 해·달은 계속 가려지는지 확인했습니다. 청크를 읽거나 다시 표시할 때 모래·자갈·모루의 낙하를 새로 예약하던 동작도 제거했습니다. 이것은 시각 효과만의 문제가 아니라 블록을 실제로 이동시키던 문제였습니다. 설치·주변 블록 변경·저장된 예약 틱으로 발생하는 정상 낙하는 유지합니다. 이전 버그로 이미 이동한 블록을 임의로 원래 위치에 되돌리지는 않습니다. [Vulkan 검증](reports/entry-twentythird-gpu-test-results.json), [일반 회귀 검사](reports/entry-twentythird-normal-test-results.json).

2026-11-08 가시성 계산 개선: 청크의 연결 정보 128바이트를 연속으로 보관합니다. 청크당 전체 데이터 크기 8,320바이트와 원본 탐색 순서·가시성 마스크는 유지합니다. 이 PC의 1600×900 이동 비교에서 해당 계산의 프레임당 평균은 16청크 0.202→0.161ms, 기존 시드 128청크 0.861→0.485ms, 새 시드 128청크 1.156→0.593ms였습니다. 전체 FPS는 각각 740→739, 252→254, 197→218로 결과가 다르며, 드문 긴 프레임은 남아 있습니다. 새 시드의 첫 플레이 화면은 0.663초였고 먼 지형은 이후에도 계속 준비합니다. 일반 검사 711개와 Vulkan 비교 8개를 통과했습니다. [검증](reports/entry-twentysixth-validation-summary.json), [16·128청크 비교](reports/entry-twentysixth-graph-comparison.json), [새 시드 비교](reports/entry-twentysixth-fresh-graph-comparison.json), [채택 판단](reports/entry-twentysixth-decision.json).

2026-11-08 큰 투명 지형 정렬 개선: 정렬할 청크가 32개 이상이고 사각형이 98,304개 이상일 때 보조 스레드 하나와 작업을 나눕니다. 랜덤 틱 섹션과 유체·낙하·불의 예약 틱 후보 목록은 청크 준비 스레드에서 계산하고, 블록 변경 시 해당 항목만 갱신합니다. 원본의 틱 대상 거리·순서·난수 소비는 줄이지 않습니다. 몹 길찾기와 이동 경로 검사에서는 주변 청크를 배열로 참조해 청크 해시맵의 반복 검색을 줄입니다. 한 번의 갱신이 끝나면 이 참조를 버리며, 다음 갱신은 변경된 월드를 다시 읽습니다. 추가 좌표별 판정 캐시는 원본 1,800개 경로 전체 측정에서 더 느려 실제 월드 경로에서는 사용하지 않습니다.

실제 청크 생성을 포함한 자동 비행 측정은 아래 명령을 사용합니다. 초당 12블록씩 이동하며 프레임 간격과 1% low, 청크 발행·메시 업로드·시뮬레이션 단계별 시간을 기록합니다. 이 실행은 기존 저장을 수정하지 않습니다. 기본 회전 카메라 벤치마크와 구분해서 비교하세요.

```bat

start.bat --benchmark --benchmark-streaming --benchmark-distant-ready --creative --seed 8924706420471469774 --render-distance 128 --seconds 20 --benchmark-output-dir reports\streaming-128
```

## 저장과 호환 범위

원본 `.minecraft`의 JAR, `level.dat`, `.mca`, 플레이어 파일은 읽기만 합니다. 블록 변경·위치는 `saves/<key>.json`, 생존 상태·인벤토리·몹·드롭·상자/화로는 같은 이름의 `.player.json`에 저장합니다. 새 월드 목록은 `worlds`에 저장합니다. 이것은 원본 Minecraft에서 직접 여는 Anvil 저장 형식이 아닙니다. `--fresh`는 이전 프로젝트 저장을 무시하며, 그 상태로 저장하면 해당 프로젝트 저장을 대체합니다.

**남은 차이:** DEFAULT 외 월드 종류의 전체 population, 생성과 게임 틱 사이의 모든 콜백/난수 순서, 전 블록의 정확한 특수 모델·충돌, 스카이라이트/블록 조명 전파, 반투명 물·유리, 텍스처 애니메이션, 전 몹·원본 AI/스폰 규칙, 기존 월드 엔티티 전체 가져오기, 모든 제작법·레시피 특수 처리, 인챈트와 임의 아이템 NBT, 레드스톤·화재/피스톤/모루 등 나머지 블록 틱, 농사·번식의 전체 규칙, 네더/엔드·포털, 완전한 서버 동기화·정품 인증은 아직 원본과 동등하지 않습니다. 기존 월드의 미생성 청크를 원본 방식으로 생성하지 않습니다. 일부 미지원 블록은 큐브 근사 또는 누락 텍스처로 나타납니다. 리소스 파일을 모두 가져온 것과 해당 게임 동작을 모두 구현한 것은 별개입니다.

## 실험용 서버 연결

메인 메뉴에서 **멀티플레이 → 직접 연결**을 누르거나 서버를 추가해 접속합니다. 기본 예시 서버 두 개는 미리보기입니다. CLI로도 상태 조회와 직접 연결을 할 수 있습니다.

```bat
start.bat --server-status 127.0.0.1:25565
start.bat --connect 127.0.0.1:25565 --username FerrumPlayer
```

채팅은 **T**, 명령은 **/**, 서버 자동완성은 **Tab**입니다. 원격 월드에서는 서버가 보내는 청크·체력·인벤토리·난이도 등을 사용합니다. Play 수신 패킷 74종에 디코드/제어 경로가 있지만 게임의 모든 동작이 동일하지는 않습니다. 온라인 모드에는 별도로 발급받은 유효한 Minecraft 세션이 필요합니다. 정상 계정 설정, 실제 원본 서버 왕복 테스트, 구현 범위와 제한은 [프로토콜 문서](docs/protocol-47.md)에 있습니다. 공개 서버의 안티치트 판정은 검증하지 않았습니다.

`tools/java/*Oracle.java`와 `scripts/test_vanilla_*.py`는 소유한 로컬 JAR의 실제 구현을 호출합니다. 자체 기대값만 작성한 테스트와 구분합니다. 일반 회귀 검사에는 이동/허기/AI/생존/수량 보존/저장/통신/GUI가 포함됩니다. Python Anvil 검사는 gzip/zlib/비압축 청크, 음수 좌표와 메타데이터, 스폰에서 멀리 저장된 플레이어와 개인 스폰, 잘못된 저장 거부를 포함한 7개 시나리오를 확인합니다. 통과한 개별 fixture를 전체 게임 100% 호환 판정으로 확대하지 않습니다.

Vulkan 자체 PNG 캡처와 네이티브 창 렌더링 루프를 검증합니다. Windows 자동화 도구의 창 캡처는 두 번 모두 시간 초과되어, 실제 마우스·키 주입 검증은 완료하지 못했습니다. 스크린샷의 인벤토리/몹 장면에는 화면 검증용 아이템·개체를 배치하며 실제 새 서바이벌 월드는 빈 소지품으로 시작합니다.

실제 1.8.9 Java 클라이언트와 Rust/Vulkan을 같은 GPU, 월드, 카메라, 해상도와 그래픽 설정으로 비교할 수 있습니다. 두 창에서 예열 후 실제 표시된 프레임 사이의 간격을 저장하며, 각 실행의 1% low는 가장 느린 1% 프레임의 평균 시간으로 계산합니다. 재현 명령과 측정 조건은 [벤치마크 안내](docs/benchmark.md)에 있습니다.

아래 v0.2~v0.4 기록은 움직이는 카메라를 사용한 과거 Rust 단독 측정입니다. 단독 측정은 `reports/benchmark.json`에 기록하며 `--entity-culling true` 또는 `false`로 컬링 조건을 고정할 수 있습니다.

## 로컬 원본 자료 준비

```bat
decompile.bat

```

`scripts/prepare_reference.py`는 MCP stable 22, SpecialSource, CFR로 소유한 JAR의 이름 매핑과 디컴파일을 수행합니다. 출력은 `.local/reference/java`입니다. 암호 해제가 아니며 원래 주석·지역 변수명까지 복원하지는 않습니다. `scripts/prepare_resources.py`는 원본 리소스를 가져오고 공식 asset index의 SHA-1을 검증합니다. 게임 자산·디컴파일 소스·개인 저장·빌드 출력은 Git에서 제외합니다.
